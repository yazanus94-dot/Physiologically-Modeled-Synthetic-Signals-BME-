# ECG Denoising Pipeline Comparison

Personal practice project comparing four classic denoising approaches
(and a realistic combined clinical pipeline) on the same noisy ECG
signal — where the clean ground truth is known, so SNR improvement and
RMSE are objective scores rather than visual impressions.

This project runs **two separate experiments**, and their numbers are never
mixed:

| Experiment | Data | Where |
|---|---|---|
| Synthetic (seeded generator) | generated by `src/generate_noisy_signal.py` | `outputs/metrics.json` |
| **Real PhysioNet NSTDB** | MIT-BIH records + real recorded noise | `outputs/real/` |

## ⚠️ Data sources — please read

### Synthetic pipeline (original build)

Built without internet access to PhysioNet: the ECG is **synthetic**
(`src/generate_noisy_signal.py`), a sum-of-Gaussians clean generator with
three independently-injected artifact sources on top — baseline wander,
50 Hz powerline interference, and EMG-like broadband noise. That clean
reference is exactly what enables the objective scoring.

### Real pipeline (added later)

The same five denoising methods now also run on the **MIT-BIH Noise Stress
Test Database (NSTDB)** from PhysioNet, downloaded into
`data/physionet/nstdb/` plus `data/physionet/mitdb/`:

- **Clean ECG** comes from real MIT-BIH records (default `118`, `119`),
  so the "clean" reference is a real recording rather than a generator.
- **Noise** comes from the three real recorded noise records — `bw`
  (baseline wander), `ma` (muscle/EMG artifact), `em` (electrode motion
  artifact) — recorded from physically active volunteers with standard
  ECG equipment.
- The two are mixed at a **precisely controlled target SNR** by
  `src/noise_mixer.py`, which resamples to a common rate, aligns, and
  scales the noise so the achieved SNR equals the requested SNR to within
  1e-9 dB (verified by test).

**Downloaded PhysioNet data is never committed to this repository** —
`data/` is git-ignored. Re-download with:

```bash
python -c "import sys; sys.path.insert(0, 'src'); from load_real_ecg import download_records; download_records()"
python -c "import sys; sys.path.insert(0, 'src'); from load_real_noise import ensure_downloaded; ensure_downloaded()"
```

**This is a learning/demonstration project**, not a clinical tool, and no
clinical claim is made or implied.

## What it does

1. **Corruption** (`generate_noisy_signal.py`) — 30 s of clean synthetic
   ECG at 250 Hz, corrupted with baseline wander, 50 Hz powerline
   pickup, and EMG-like broadband noise.
2. **Real mixing** (`load_real_ecg.py`, `load_real_noise.py`,
   `noise_mixer.py`) — load real ECG and real noise from PhysioNet and
   mix them at an exact target SNR.
3. **Denoising methods** (`denoise_methods.py`):
   1. Median-filter baseline removal (classic clinical baseline-wander
      correction)
   2. Butterworth bandpass filtering (standard 0.5–40 Hz ECG passband)
   3. IIR notch filter targeted at the powerline frequency
   4. FFT-domain soft-thresholding denoiser (a frequency-domain analogue
      of wavelet soft-thresholding, without needing a wavelet library)
   5. A combined pipeline (1 → 3 → 2), the shape of a real clinical
      front-end chain
4. **Evaluation** — SNR improvement, RMSE, NRMSE, PRD, Pearson
   correlation, and R-peak detector sensitivity/precision/MAE against the
   clean reference, plus plots.

### Scoring convention (DC-offset correction)

Waveform-error metrics (`rmse`, `nrmse`, `prd`, `snr_db`) are computed
after **removing the mean from both** the reference and the estimate.
Real MIT-BIH segments carry a mean of roughly −0.33 mV, and a filter that
legitimately removes DC would otherwise be penalised about 23 dB for doing
its job. This is applied consistently to every method, the synthetic
comparison, and the real experiment, so no method gains an unfair
advantage. `pearson` correlation is unaffected by a constant offset.

## Results

All numbers below are **measured by these runs**; `outputs/metrics.json`
and `outputs/real/results_summary.csv` are the authoritative records.

### Synthetic (seed 3, 30 s at 250 Hz, raw SNR −0.85 dB)

| Method | SNR improvement | RMSE |
|---|---:|---:|
| Butterworth bandpass (0.5–40 Hz) | **+16.34 dB** | 0.0324 |
| Combined pipeline (median → notch → bandpass) | +15.07 dB | 0.0375 |
| FFT soft-thresholding | +8.76 dB | 0.0777 |
| Median-filter baseline removal | +8.63 dB | 0.0788 |
| 50 Hz notch alone | +0.33 dB | 0.2049 |
| *(raw noisy, reference)* | *0.00 dB* | *0.2129* |

Straightforward reading: the bandpass gives the biggest single-step
improvement because it removes all three artifact classes at once; the
combined clinical-style pipeline is close behind while retaining each
step's specific role; the notch alone is nearly neutral — expected, since
powerline content is a small fraction of the total corruption on its own.

> **Note:** an earlier revision of this README reported "+7.17 dB" for the
> bandpass. That figure was polluted by the DC-offset issue described
> above: the raw score included a mean offset that the high-pass stage
> correctly removed. The +16.34 dB figure is the DC-corrected score and is
> the one now produced by `outputs/metrics.json`.

### Real PhysioNet NSTDB (`outputs/real/`)

**Records:** **MIT-BIH records `118` and `119`** (both downloaded from
PhysioNet with their `.atr` beat annotations — the original audit
specified 118/119; the earlier revision used 100/101).

**Data mixing:** clean MIT-BIH ECG was mixed with the real NSTDB
noise records at an **exactly requested target SNR**.  The mixer
re-scales the noise to hit the target to within ~1e-15 dB: the
experiment prints `Mixer accuracy: max |achieved - target| = 3.55e-15 dB`
and the per-cell `achieved_snr_db` column is verified by
`tests/test_real_experiment.py::test_real_achieved_snr_matches_target`
(asserts deviation < 1e-6 dB).

**Configuration (master spec):** each cell (3 noise types × 6 SNR levels
× 2 ECG records) was evaluated on **10 independent noise segments per
cell** (the master configuration; the audit asked for ≥ 5), 10 s
segments, per-segment reproducible seeds
(`np.random.default_rng([seed, seg, target+100, name lengths])`).
Run: `run_real_experiment.py --download` (defaults: records 118/119,
duration 10 s, segments 10, seed 3).  **Result: 2,160 segment rows**
(10 × 3 noise × 6 SNR × 2 records × 6 methods); all 6 SNR levels and
all 3 noise types present (asserted by
`test_real_segments_have_at_least_ten_per_cell`,
`test_real_segments_cover_all_snr_levels_and_noise_types`); 108 summary
rows asserted by `test_real_summary_has_a_row_per_cell_and_method`.

**Peak matching tolerance:** the predefined **±150 ms** one-to-one
matching tolerance is used everywhere and was **not** tuned to the data
(`evaluate_denoising.DEFAULT_PEAK_TOLERANCE_S = 0.15`, asserted by
`test_peak_tolerance_is_predefined_150ms`; recorded in
`metrics.json` as `peak_tolerance_ms`).

**Mean SNR improvement (dB) per cell, averaged over the 10 segments and
both records:**

| Target SNR | Bandpass 0.5–40 | Combined | Median | FFT soft-thr. | Notch 50 Hz |
|---:|---:|---:|---:|---:|---:|
| −6 dB | **+17.00** | +18.21 | +18.18 | +13.87 | +0.00 |
| 0 dB | **+13.95** | +13.11 | +14.17 | +10.96 | +0.00 |
| +6 dB | **+10.22** | +8.47 | +10.51 | +7.33 | +0.00 |
| +12 dB | **+5.43** | +3.38 | +5.88 | +2.22 | +0.00 |
| +18 dB | −0.43 | −2.24 | +0.20 | −3.56 | −0.00 |
| +24 dB | −6.44 | −8.24 | −5.75 | −9.64 | −0.01 |

**R-peak detection (bandpass, per cell):** sensitivity 0.9920,
precision 0.4390, **F1 = 0.6063** (combined: 0.9913 / 0.4372 / 0.6045;
aggregate F1 mean ≈ 0.60).  `F1 = 2·precision·sensitivity /
(precision + sensitivity)` (`evaluate_denoising._peak_f1`), added to
trial-level CSV, summary CSV, and JSON — see
`tests/test_denoising.py::test_rpeak_f1_metric`.

**Morphology preservation (mean relative change, 0 = perfect;
bandpass):** QRS amplitude **+0.066**, QRS width **−0.167** — the
high-pass keeps a positive amplitude bias and slightly narrows the QRS
vs. the clean reference; the combined pipeline is similar.

**Powerline ablation (separate experiment, see below).**

What this shows:

- **Gains are positive and largest at low SNR** (−6 … +6 dB), where there
  is real noise to remove — the physically expected behaviour.
- **Gains become negative at high SNR** (+18, +24 dB). When the
  recording is already clean, filtering removes signal content along with
  almost no noise, so it costs more than it gains.
- **The notch alone is essentially neutral** across the whole range
  (NSTDB's powerline content is one of three noise sources; the `em` and
  `ma` records dominate the gain structure).

### Powerline ablation (controlled 50 Hz / 60 Hz mains interference)

To evaluate the notch filter independently of the NSTDB noise
experiments, `run_real_experiment.py` generates **controlled powerline
interference on the clean ECG**: a sinusoid at the standard mains
frequency (both 50 Hz and 60 Hz) added to the clean MIT-BIH reference at
two amplitudes (0.05 mV, 0.10 mV).  Methods are evaluated on these
signals against the clean-ECG reference (using `.atr` peaks).

Ablation results (mean SNR improvement over the clean ECG, 4 trials per
cell — 2 records × 2 amplitudes):

| Interference | Notch @ matching | Notch @ other | Bandpass | Median |
|---|---:|---:|---:|---:|
| 50 Hz | **+39.64 dB** | +18.37 dB | +11.73 dB | +10.82 dB |
| 60 Hz | **+42.01 dB** | +18.35 dB | +11.76 dB | +10.82 dB |

The notch is ~2× stronger when tuned to the actual interference than
when mismatched, but the bandpass is almost as good — showing why the
notch needs to be set to the local mains frequency.  Results are in
`outputs/real/powerline_ablation.json` (32 rows) and
`powerline_ablation_snr.png`.  This is separate from the NSTDB
experiments: it uses the same shared 150 ms matching tolerance and
`compute_segment_metrics`, so the metric definitions are identical.

Plots (real): `outputs/real/snr_improvement_by_snr.png`,
`nrmse_by_snr.png`, `rpeak_sensitivity_by_snr.png`,
`rpeak_f1_by_snr.png`, `sample_waveforms.png`, **`rmse_by_method.png`**,
**`prd_by_method.png`**, **`morphology_by_method.png`**,
**`noise_type_comparison.png`**, **`powerline_ablation_snr.png`**.

Machine-readable record: `outputs/real/metrics.json` (records,
methodology, `peak_tolerance_ms`, `achieved_snr_db` with
`verified_achieved_vs_target`, aggregate metrics incl. F1, and
`powerline_ablation` summary).

### R-peak matching-tolerance sensitivity (P2.1)

The predefined ±150 ms tolerance is used everywhere (§ "Peak matching
tolerance" above).  Independently of the benchmark-facing result, a
**tolerance sensitivity analysis** recomputes the bandpass-method R-peak
metrics at **±50, ±100 and ±150 ms** (outputs/real/tolerance_sensitivity.json +
tolerance_sensitivity.png), without choosing the "best" — the predefined
tolerance stays authoritative.  Example (baseline_wander, −6 dB):

| Tolerance | Sensitivity | Precision | F1 | MAE |
|---:|---:|---:|---:|---:|
| ±50 ms | 0.818 | 0.290 | 0.429 | 3.09 ms |
| ±100 ms | 0.909 | 0.323 | 0.476 | 10.28 ms |
| ±150 ms | 0.909 | 0.323 | 0.476 | 10.28 ms |

The tolerance analysis is covered by
`tests/test_real_experiment.py::test_tolerance_sensitivity_analysis`.

### SNR conventions (P2.2) — two, deliberately distinguished

Two different conventions appear in the CSVs/JSON, because they are
different physical quantities:

- **Mixer convention (power ratio, DC-inclusive):** the noise mixer
  scales the noise so that `SNR_dB = 10·log10(P_signal / P_noise)` with
  `P = mean(x²)` (`noise_mixer.py:14–18, 74–94`).  Stored per row as
  `achieved_snr_db` (renamed, canonical, as
  `achieved_power_ratio_snr_db` in the same rows) and
  `achieved_power_ratio_snr_db`.
- **Waveform-error convention (AC, DC-removed):** the waveform metrics
  (`rmse`, `nrmse`, `prd`, `snr_db`) are computed after removing the mean
  from **both** the reference and the estimate (`_zero_mean`).
  Stored per row as `input_ac_snr_db` (DC-removed SNR of the mixture),
  `output_ac_snr_db` (DC-removed SNR of the denoised output) and
  `snr_improvement_ac_db = output − input`.

Both conventions are recorded in the aggregate
(`input_ac_snr_db_mean/std`, `output_ac_snr_db_mean/std`,
`snr_improvement_ac_db_mean/std`) and both are pinned in
`metrics.json.versions` + `peak_tolerance_ms` + `verified_achieved_vs_target`.

### Reproducible experiment report (P2.4)

- `outputs/real/report.json` — full provenance (records 118/119,
  methodology, tolerance, versions, aggregate stats).
- `outputs/real/report/report_waveforms.png` — clean, noisy, denoised
  (bandpass) and error waveform for the panel segment (DC-removed).
- `outputs/real/report/report_rpeak.png` — R-peak overlay: clean
  signal + reference peaks (`.atr`) + detected peaks of the bandpass
  method.

### Optional expanded evaluation (P2.3)

An optional expanded run on additional annotated MIT-BIH records can be
run with `--extra-records "207,214"`; results are written to a
**separate** directory `outputs/real_expanded/` — the primary benchmark
(records 118/119) is never mixed into or overwritten.  Rows are tagged
`protocol_tag="expanded_extra"` and every row carries its ECG/noise
record IDs (`ecg_record`, `noise_record`, `noise_category`), so the two
benchmarks stay separately identifiable.
