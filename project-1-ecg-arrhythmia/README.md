# ECG Arrhythmia Beat Classification (Pan-Tompkins R-peak Detection + Random Forest)

Personal practice project applying a classic biomedical signal processing
pipeline to ECG beat classification: R-peak detection, beat-level feature
extraction, and a Normal / PVC / Supraventricular / Fusion beat classifier.

This project runs **three separate experiments**, and their numbers are
never mixed:

| Experiment | Data | Where |
|---|---|---|
| Synthetic (seeded generator) | generated by `src/generate_signal.py` | `outputs/synthetic/` |
| **Real MIT-BIH Arrhythmia Database** | 48 records downloaded from PhysioNet | `outputs/mitbih/` |
| **Detector-driven** (real MIT-BIH) | same 48 records, peaks from the detector | `outputs/detector_driven/` |

## ⚠️ Data sources — please read

### Synthetic pipeline (original build)

The project began in an environment without internet access to PhysioNet, so
the original pipeline uses a **physiologically-informed synthetic ECG
generator** (`src/generate_signal.py`). It builds P-QRS-T morphology from a
sum-of-Gaussians model (the same style of approach used by tools like
ECGSYN), with realistic baseline wander, powerline interference, and EMG-like
noise added on top.

### Real pipeline (added later)

The same detector, features, and classifiers now also run on the **real
MIT-BIH Arrhythmia Database**, downloaded from PhysioNet into
`data/physionet/mitdb/` (48 records, 144 files, 93.9 MB, 0 failures).

**Downloaded PhysioNet data is never committed to this repository** —
`data/` is git-ignored. Re-download with:

```bash
python -c "import sys; sys.path.insert(0, 'src'); from load_mitbih import MITBIHLoader; MITBIHLoader().download_database()"
```

**This is a learning/demonstration project, not a submission to any
PhysioNet/Computing in Cardiology Challenge, and no clinical-validation
claim is made.** The synthetic numbers and the real numbers are reported
separately throughout, and neither is a claim of clinical performance.

## What it does

1. **Signal generation** (`generate_signal.py`) — 10 minutes of synthetic
   ECG at 250 Hz, with randomly interspersed Normal (N), PVC (V), and
   supraventricular/other (S) beats, each with distinct morphology,
   premature timing for V/S beats, and a compensatory pause after PVCs.
2. **Real record loading** (`load_mitbih.py`) — WFDB download and loading of
   MIT-BIH records, ECG channel selection, and retrieval of the reference
   `atr` annotations.
3. **R-peak detection** (`detect_rpeaks.py`) — a Pan-Tompkins-style
   detector implemented from scratch with `scipy`: bandpass filter →
   derivative → squaring → moving-window integration → adaptive
   thresholding with a refractory period. Scored one-to-one against the
   reference peaks (each detected peak may match at most one reference
   peak), tolerance ±50 ms.
4. **Preprocessing + AAMI mapping** (`preprocessing.py`, `aami.py`) —
   resampling to a common rate, and mapping the full MIT-BIH symbol set
   onto the four AAMI classes `N / S / V / F`.
5. **Feature extraction** (`features.py`) — 14 beat-level features:
   RR-interval context (pre/post RR, local mean, RR ratio, prematurity
   ratio — capturing prematurity) plus QRS morphology (amplitude, width,
   energy, beat mean/std/var/skew/kurtosis, relative R amplitude —
   capturing the wide/bizarre PVC shape).
6. **Classification** (`train_model.py`, `evaluation.py`, `run_pipeline.py`)
   — Random Forest and Logistic Regression classify each beat, evaluated
   with an explicit `labels=` list alongside `target_names` (sklearn sorts
   label names alphabetically, so omitting `labels` silently shifts the
   class names in the report).

### Evaluation protocols (real data)

Both protocols are **patient-level**: beats from one record never appear in
both train and test.

- **`classic`** — the classic DS1/DS2 split: 18 train records + 4
  validation records from DS1, 22 test records from DS2. Test set: 49,661
  beats (N=44,218, S=1,836, V=3,219, F=388).
- **`leakage_audited`** — the same split after auditing for
  same-subject leakage. Records 201 and 202 originate from the same subject
  (stated in the MIT-BIH documentation); 201 is in train, so **202 is
  excluded from test**. Test set: 47,527 beats (N=42,159, S=1,781,
  V=3,200, F=387). The audit prints `No subject leakage detected`.

### Annotation-centred (retrospective) vs detector-driven

These are two *different* questions, and this repo answers both without
mixing their numbers.

| | **Annotation-centred** (`classic`, `leakage_audited`) | **Detector-driven** (`outputs/detector_driven/`) |
|---|---|---|
| Where do beat windows come from? | Expert `.atr` annotation positions (`aami.segment_beats_annotation_centered`) | The from-scratch Pan-Tompkins-style detector (`detect_rpeaks`) |
| What are the RR features? | `extract_rr_features_for_annotations` — **annotation timing**, including the future-dependent `rr_next` | `_causal_rr_features` — **detected-peak timing**, past intervals only |
| What are the labels? | The annotation's own AAMI class | Assigned **only** to detections matched one-to-one (±50 ms) to a reference annotation |
| What is it for? | An upper bound: *"if we already know exactly where every beat is, how well can morphology + timing separate the classes?"* | The deployable question: *"given only the signal and our own detector, what would a real system achieve end to end?"* |
| Retrospective? | **Yes — by design.** It uses information (annotation positions) that is only available after a human has labelled the record. It is a **reference-centred benchmark**, not a simulation of a running system. | **No.** Feature inputs are `(signal, detected peaks)` only. Annotations enter **solely** as evaluation labels through one-to-one matching. |

**Why the annotation-centred run is kept.** It is the honest reference
point: it isolates classifier quality from detector quality, and it is
the protocol the published DS1/DS2 numbers use. Removing it would make
the detector-driven numbers uninterpretable — you could no longer tell
whether a drop came from the classifier or from missed beats.

**What the detector-driven run adds.** It reports, per protocol:

- matched detections (TP), **unmatched detections** (FP) and **missed
  reference beats** (FN) — detection errors are counted, never hidden by
  silently dropping them;
- classification metrics (balanced accuracy, macro-F1, per-class
  precision/recall/F1) **on matched detections only**;
- the combined end-to-end limitation: a beat the detector misses can
  never be classified, so end-to-end performance is bounded above by the
  detector's own sensitivity/precision (0.9434 / 0.9560 pooled, above).

**Leakage guard.** Annotation *positions* are never used to build
detector-driven input features — `tests/test_detector_driven.py`
asserts that the feature names contain no annotation-derived column and
that labels come only from the one-to-one match.

**Causal feature configuration** (audit Phase 3.6). The detector-driven
run defaults to `feature_config="causal_no_rr_next"`
(`features.FEATURE_CONFIGS`): every RR feature that needs a **future
beat** is excluded —

| Feature | Needs a future beat? | Why |
|---|---|---|
| `rr_prev` | no | interval ending at this beat |
| `rr_next` | **yes** | interval to the *following* beat |
| `rr_mean_local` | **yes** | the local mean also averages intervals after this beat |
| `rr_ratio` | **yes** | `rr_next / rr_prev` |
| `prematurity_ratio` | **yes** | `rr_prev / rr_mean_local` |

so the causal set keeps `rr_prev` plus the morphology columns (10 of the
annotation-centred 14). The chosen configuration and the excluded names
are written into `outputs/detector_driven/metrics.json`
(`feature_config`, `future_dependent_features_excluded`).
`annotation_centred_full` selects everything and is what the
retrospective benchmark uses — that benchmark and its committed results
are unchanged.

## Run it

```bash
pip install -r requirements.txt

# synthetic pipeline
cd src && python run_pipeline.py --mode synthetic && cd ..

# real MIT-BIH: downloads data on first run if missing
cd src && python run_pipeline.py --mode mitbih --protocol classic && cd ..
cd src && python run_pipeline.py --mode mitbih --protocol leakage_audited && cd ..

# R-peak detector evaluation on real MIT-BIH
cd src && python run_pipeline.py --mode rpeaks && cd ..

# detector-driven classification (causal features, annotations used only
# for one-to-one label matching) -> outputs/detector_driven/
cd src && python run_detector_driven.py && cd ..
```

Output (metrics + plots) is written to `outputs/`.

## Results

All numbers below are **measured by these runs**; `outputs/**/metrics.json`
and `outputs/mitbih/*/rpeak_detection.json` are the authoritative records.

### Synthetic (seed 42, 10 min of 250 Hz synthetic ECG, 739 beats)

- R-peak detector: **100.0% sensitivity, 100.0% precision** vs. ground
  truth (±50 ms, one-to-one matching; TP=739, FP=0, FN=0), mean timing
  error 6.37 ms.
- Beat classifier: **1.00 accuracy / 1.00 macro-F1** for N, V and S on the
  held-out split.

This is expected and **not claimed as real-world performance** — the
synthetic morphologies are more cleanly separable by construction than
real, noisy clinical ECG. The real MIT-BIH numbers below show the gap.

### Real MIT-BIH — R-peak detection (`--mode rpeaks`)

44 records evaluated (records 102/104/107/217 are outside the DS1/DS2
protocol and are skipped), one-to-one matching at ±50 ms against the
expert `atr` annotations:

| | |
|---|---:|
| True positives | 95,014 |
| False positives | 4,369 |
| False negatives | 5,704 |
| **Pooled sensitivity** | **0.9434** |
| **Pooled precision** | **0.9560** |
| **Pooled F1** | **0.9497** |
| Mean timing error | 3.79 ms (SD 14.28 ms across records) |

Worst records by F1 — reported deliberately, not filtered out:

| Record | Sensitivity | Precision | F1 | Note |
|---|---:|---:|---:|---|
| 228 | 0.348 | 0.906 | 0.503 | paced/beats the band attenuates; 1,338 missed |
| 215 | 0.697 | 0.697 | 0.697 | 1,019 FP / 1,019 FN |
| 124 | 0.801 | 0.805 | 0.803 | |
| 117 | 0.821 | 0.821 | 0.821 | |
| 203 | 0.837 | 0.847 | 0.842 | |

### Real MIT-BIH — beat classification

| Protocol | Model | Balanced acc. | Macro-F1 | Weighted-F1 | Accuracy |
|---|---|---:|---:|---:|---:|
| `classic` | Random Forest | 0.6413 | 0.4766 | 0.8555 | 0.8253 |
| `classic` | Logistic Regression | 0.7063 | 0.5581 | 0.8882 | 0.8551 |
| `leakage_audited` | Random Forest | 0.6405 | 0.4806 | 0.8565 | 0.8285 |
| `leakage_audited` | Logistic Regression | 0.7081 | 0.5689 | 0.8943 | 0.8661 |

Reading these honestly: accuracy and weighted-F1 look high because the
`N` class dominates (~89% of test beats). **Balanced accuracy and macro-F1
are the meaningful numbers here**, and they are far below the synthetic
1.00 — which is exactly what patient-independent classification on real
MIT-BIH looks like. The rare classes (`S`, `F`) are what drag macro-F1
down; per-class precision/recall is in `outputs/mitbih/*/metrics.json`.

Excluding the same-subject record 202 (`leakage_audited`) moves the numbers
by less than 0.01 — the split was already close to leakage-free, and the
audit confirms it.

### Real MIT-BIH — detector-driven classification

Same DS1/DS2 split, but the features now come from the **detector's own
peaks** and the labels only from one-to-one matching (±50 ms). Causal
feature configuration `causal_no_rr_next` (no future-beat RR features).

Detection side, test records only (from `outputs/detector_driven/metrics.json`):

| | |
|---|---:|
| Matched detections (TP) | 46,029 |
| Unmatched detections (FP) | 1,707 |
| Missed reference beats (FN) | 5,106 |
| Implied sensitivity / precision | 0.8999 / 0.9646 |

Classification side (test classes: N=41,009, S=1,778, V=2,868, F=374):

| Model | Balanced acc. | Macro-F1 |
|---|---:|---:|
| Random Forest | **0.5014** | 0.4765 |
| Logistic Regression | **0.2515** | 0.2386 |

Reading this honestly — it is the *least* flattering table in the repo and
that is the point:

- **Detector-driven is worse than annotation-centred**, as it should be.
  RF balanced accuracy falls 0.6413 → 0.5014 and LR 0.7063 → 0.2515. The
  annotation-centred numbers are an upper bound obtained with information
  (exact beat positions, annotation timing) that is not available at
  inference time.
- **The rare classes collapse.** RF recalls S at 0.041 and F at 0.083
  (F1 0.052 and 0.026); LR recalls neither at all (0.000). V, the class
  with the most distinctive morphology, is recalled at 0.959 by RF.
- **End-to-end is bounded by the detector.** A beat the detector misses
  (5,106 of them) can never be classified, and an unmatched detection
  (1,707) can never be correct — so no classifier downstream can exceed
  the detector's own 0.8999 / 0.9646 on this test set.
- **The three differences are confounded.** Annotation-centred and
  detector-driven differ in peak positions *and* RR-feature definitions
 *and* label assignment simultaneously, so the gap above cannot be
  attributed to any one of them. Isolating them would need an ablation
  this project does not run — recorded as a limitation, not glossed over.

### Documented engineering decisions

- **Widened detection band.** The classic Pan-Tompkins passband (~5–15 Hz)
  attenuates the deliberately wide PVC morphology so badly that every PVC
  was missed in early versions of this build; the band was widened to
  2–15 Hz, validated on eight independent generator seeds. Keeping the
  stricter band would have produced a "more honest" ~85% detector — but a
  detector that misses a whole arrhythmia class cannot honestly support the
  classification stage, so the widened band was adopted.
- **Explicit `labels=` in `classification_report`.** sklearn sorts label
  names alphabetically, so passing only `target_names` shifts every class
  name in the report. All reports pass `labels` explicitly.
