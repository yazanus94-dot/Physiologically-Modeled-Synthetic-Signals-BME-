# PPG-Based Heart Rate Variability (HRV) Estimation

Personal practice project: systolic peak detection from a PPG
(photoplethysmogram) waveform, and time-domain + frequency-domain HRV
analysis from the resulting pulse-to-pulse interval series — following
the Task Force (ESC/NASPE) HRV metric conventions (SDNN, RMSSD, pNN50,
LF/HF ratio).

This project runs **two separate experiments**, and their numbers are never
mixed:

| Experiment | Data | Where |
|---|---|---|
| Synthetic (seeded generator) | generated by `src/generate_ppg.py` | `outputs/metrics.json` |
| **Real PhysioNet BIDMC** | 3 real ICU recordings (PPG + ECG) | `outputs/real/` |

## ⚠️ Data sources — please read

### Synthetic pipeline (original build)

Built without internet access to PhysioNet, so the original pipeline uses
a **physiologically-motivated synthetic PPG generator**
(`src/generate_ppg.py`) — an asymmetric double-Gaussian pulse model
(systolic peak + dicrotic notch) with realistic **respiratory sinus
arrhythmia** modulation (the dominant real physiological driver of
short-term HRV: heart rate oscillates with the breathing cycle) and
randomly-injected **motion-artifact noise bursts**, rather than a real
downloaded PPG recording.

### Real pipeline (added later)

The same detector and metric code now also run on the **BIDMC PPG and
Respiration Dataset** from PhysioNet, downloaded into
`data/physionet/bidmc/` (records `bidmc01`–`bidmc03`, 480.008 s each at
125 Hz; signals `RESP, PLETH, V, AVR, II`, numerics at 1 Hz).

**Downloaded PhysioNet data is never committed to this repository** —
`data/` is git-ignored. Re-download with:

```bash
python -c "import sys; sys.path.insert(0, 'src'); from load_bidmc import download_records; download_records()"
```

**This is a learning/demonstration project, not a PhysioNet/Computing in
Cardiology Challenge submission, and no clinical claim is made or implied.**

### HRV vs PRV — a distinction this project keeps explicit

The two interval series are **not the same physiological quantity**:

- **HRV** here is computed from **ECG R–R intervals** (WFDB `XQRS`
  detector on lead II).
- **PRV** is computed from **PPG pulse-to-pulse intervals** (this
  project's own peak detector on the `PLETH` channel).

They are compared, but never presented as interchangeable. Every table
labels which one it is showing.

### `lag_s` is an inter-channel alignment lag — not a pulse transit time

`lag_s` is estimated by cross-correlating the two *interval series* to
find the offset that best aligns them. It is a **fixed inter-channel
alignment offset** between the recorded `PLETH` and `II` channels, and it
is explicitly **not** a pulse transit time (PTT): the measured PLETH
systolic peak falls essentially *at* the R-peak (median offset −16 … +16
ms across the three records), which is physiologically impossible for a
real PTT. The value is used only to align the two series before computing
their correlation; a constant offset cancels out of all interval-based
metrics.

## What it does

1. **Signal generation** (`generate_ppg.py`) — 3 minutes of synthetic PPG
   at 100 Hz with HRV driven by a simulated 0.25 Hz respiration cycle,
   plus sensor noise and a few short motion-artifact bursts.
2. **Real record loading** (`load_bidmc.py`) — WFDB download/loading of
   BIDMC records, channel identification from the header (`PLETH` → PPG,
   `II` → ECG), and 1 Hz bedside-monitor numerics.
3. **Peak detection** (`peak_detect.py`) — bandpass filter (0.5–8 Hz) →
   adaptive-threshold peak picking → rejection of physiologically
   implausible intervals (catches most, not all, motion-artifact false
   positives — deliberately imperfect, see results below).
4. **Preprocessing + quality** (`ppg_preprocessing.py`,
   `quality_assessment.py`) — filtering, flatline/clipping/wander checks,
   and HRV-vs-PRV interval comparison with disagreement classification
   (missed pulse / false peak / uncertain).
5. **ECG reference** (`ecg_reference.py`) — R-peak detection on the ECG
   channel, R–R interval series, and lag estimation/alignment against the
   PPG series.
6. **HRV metrics** (`hrv_metrics.py`) — time-domain (mean HR, SDNN,
   RMSSD, pNN50) and frequency-domain (VLF/LF/HF band power via Welch PSD
   of the interval series, LF/HF ratio).
7. **Pipelines** — `run_pipeline.py` runs the synthetic experiment;
   `run_bidmc_experiment.py` runs the real BIDMC HRV-vs-PRV experiment.

### Artifact rejection (real data)

Before any variability metric, both interval series are filtered to the
physiological range **40–200 bpm (0.30–1.50 s)**. Sensor dropouts and
detector dropouts otherwise enter as multi-second "intervals" and
dominate SDNN/RMSSD — a single 8 s gap inflates SDNN by hundreds of ms.
Every rejection is **counted and reported** in
`interval_artifact_rejection`, never silently discarded.

## Run it

```bash
pip install -r requirements.txt

# synthetic pipeline
cd src && python run_pipeline.py && cd ..

# real BIDMC experiment (downloads data on first run if missing)
cd src && python run_bidmc_experiment.py --download && cd ..
```

Output (metrics + plots) is written to `outputs/`.

## Results

All numbers below are **measured by these runs**; `outputs/metrics.json`
and `outputs/real/metrics.json` are the authoritative records.

### Synthetic (seed 7, 3 min of 100 Hz synthetic PPG, 205 beats)

- Peak detector: **99.51% sensitivity, 100.0% precision** vs. ground
  truth (tolerance ±150 ms; TP=204, FP=0, FN=1) — a single missed beat
  near an artifact burst.
- HRV metrics, detected vs reference:

  | Metric | Reference | Detected |
  |---|---:|---:|
  | Mean HR (bpm) | 68.37 | 68.37 |
  | SDNN (ms) | 62.32 | 59.55 |
  | RMSSD (ms) | 79.73 | 76.32 |
  | pNN50 (%) | 67.49 | 64.85 |

- Frequency domain: essentially all heart-rate power sits in the HF band
  (the simulated respiration is at 0.25 Hz, inside the 0.15–0.40 Hz HF
  band by definition), so the LF band — which in real recordings also
  carries baroreflex-mediated activity this generator does not model — is
  tiny, and LF/HF is correspondingly low (0.001 for both series).

Motion artifact remains the known dominant error mode of PPG-based HRV
in the wearables literature: in runs where an artifact bumps the adaptive
threshold, a missed detection or brief spurious interval inflates
RMSSD/SDNN sharply, exactly the failure mode real devices must handle.
The current artifact parameters happen to be handled cleanly by the
height threshold + plausibility filter (with one boundary miss), so the
run stays close to the reference — but the tachogram plot
(`outputs/rr_tachogram.png`) still marks the artifact regions where that
agreement is most fragile.

### Real PhysioNet BIDMC — ECG-derived HRV vs PPG-derived PRV

3 records, `bidmc01`–`bidmc03`, 480 s each at 125 Hz (well above the
300 s minimum-analysis-duration floor).  R-peaks from WFDB `XQRS` on
lead II (an **automated** detector — see `reference_kind.ecg_hrv` in
`outputs/real/metrics.json`); pulse peaks from this project's own
detector on `PLETH` with **local adaptive thresholds** and one-to-one
matching.  All variability is derived from these automated reference
peaks, and HRV ≠ PRV throughout.

| Record | HR ECG (bpm) | HR PPG (bpm) | SDNN ECG (ms) | SDNN PPG (ms) | Agreement | r (beat) | r (10 s smoothed) | lag (s) |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| bidmc01 | 91.29 | 91.15 | 25.78 | 31.55 | 99.7 % | 0.514 | 0.528 | 0.50 |
| bidmc02 | 91.00 | 90.77 | 16.94 | 53.42 | 98.6 % | 0.392 | 0.614 | 0.20 |
| bidmc03 | 77.00 | 76.38 | 63.16 | 56.67 | 93.6 % | 0.484 | 0.651 | 0.70 |

Aggregate (mean over the 3 records):

| Metric | Value |
|---|---:|
| Mean HR difference (PRV vs HRV) | **−0.40 %** |
| Beat agreement within tolerance | **97.3 %** |
| Interval-series Pearson r (lag-corrected) | 0.463 |
| Interval-series Pearson r (after 10 s smoothing) | 0.568 |
| Mean inter-channel alignment lag | 0.47 s |
| Mean SDNN difference | 75.82 % |
| Mean RMSSD difference | 84.58 % |
| Mean LF/HF ratio difference | 506.56 % |

Time-aligned monitor-reference comparisons (both series on a common
1 Hz grid over the overlap window, no extrapolation; MAE / bias and
Bland-Altman 95% limits of agreement).  The monitor is the
**automated bedside-monitor algorithm** (1 Hz numerics), not manual
beat annotation — the `reference_note` field states this explicitly:

| Record | ECG-derived HR vs monitor (MAE \| bias) | PPG-derived HR vs monitor (MAE \| bias) |
|---|---|---|
| bidmc01 | 1.12 \| +0.13 | 1.34 \| −0.18 |
| bidmc02 | 1.07 \| −0.09 | 2.31 \| −0.09 |
| bidmc03 | 2.85 \| +1.03 | 1.97 \| −0.01 |

Independent cross-check against the monitor's own 1 Hz numerics (not
used anywhere in the computation), time-aligned the same way:

| Record | Monitor HR | Monitor pulse | This run (ECG) | This run (PPG) |
|---|---:|---:|---:|---:|
| bidmc01 | 91.32 | 91.01 | 91.29 | 91.15 |
| bidmc02 | 91.07 | 90.66 | 91.00 | 90.64 |
| bidmc03 | 76.64 | 75.89 | 77.00 | 76.38 |

**Reading these honestly:**

- **Mean heart rate agrees closely** (−0.45 %, within 0.1 bpm of the
  monitor's own numerics in all three records) and **97.4 % of beats
  match** within tolerance.  Both series are measuring the same heart
  rate.
- **Variability metrics do *not* agree**, and this is reported as a
  finding rather than smoothed away.  The divergence is dominated by
  `bidmc02` (PPG SDNN 50.4 ms vs ECG SDNN 16.9 ms) and `bidmc03` (20
  ECG intervals rejected out of 623 as out-of-range, which deflates the
  ECG SDNN relative to PPG).  `bidmc03` is the record with the lowest
  beat agreement (93.6 %).
- **Beat-to-beat correlation is moderate (0.40–0.51) and rises to
  0.57–0.65 after 10 s smoothing.**  Both interval series are
  dominated by independent beat-to-beat peak-timing jitter rather than
  by shared physiology.  Independent noise does not cancel, so the
  raw correlation is bounded by the ratio of shared variance to total
  variance.  Averaging over 10 s suppresses the uncorrelated jitter
  and exposes the shared heart-rate trend.  **Both numbers are
  reported; neither is presented alone.**
- **LF/HF differs by ~506 % on average** — with ratios this small and
  bands this narrow over only 8 minutes of data, a percentage difference
  is a very unstable quantity (per-record values: +1453 %, +137 %,
  −70 %).  The absolute band powers are in
  `outputs/real/metrics.json`; this number should be read as "the two
  disagree substantially", not as a calibrated error.
