Audit round: corrections for the final audit (Phases 1–5), run after commit
`290c8c7`. Report date: 2026-11-23.

**Headline of this round.** The earlier rounds closed every structural item
the audit asked for, and the CI was green — but a scientific defect remained
in the benchmark's headline metric: `evaluator.snr_db` divided by the
**power of the estimate** instead of the **error power**. That is not an
SNR. Under it, `improvement = 10*log10(P_noisy / P_estimate)`, so a solution
that merely attenuated its input scored as if it had denoised it (scaling by
0.1 earned +20 dB), and the old reference pipeline was ranked against the
starter using that distorted scale. Section 2 documents the fix, the
measurement that exposed it, and the corrected results.

## 2. The defect found in this round (audit 2.5) and its correction

### 2.1 What was wrong

`evaluator.snr_db(reference, estimate)` computed

```
10*log10( P_reference / P_estimate )        # WRONG
```

instead of the standard reconstruction SNR

```
10*log10( P_reference / P_error ),  P_error = P(reference - estimate)
```

Consequences:

* A solution that returns `0.5 * noisy` earned exactly `+6.02 dB`, and
  `0.01 * noisy` earned `+40 dB`, while removing no noise.
* The metric ranked pipelines by how much energy they *attenuated*, not by
  how much error they *removed*, so it could not distinguish denoising from
  silence (only the separate structure check caught exact silence).
* The previous round's "reference beats starter by +0.51 dB" was measured
  on this scale and therefore did not mean what it claimed.

Project 2 already used the correct error-based formula
(`project-2-ecg-denoising/src/denoise_methods.py::snr_db`); the benchmark had
drifted from it. Re-measured with the correct definition, the *old* reference
(median → 50 Hz notch → 0.5–40 Hz band-pass) scored **2.62 dB**, *below* the
band-pass-only starter's **2.99 dB** — the opposite of the committed claim.
That is exactly the "compare reference vs starter" item the audit asked for,
so it had to be fixed rather than documented away.

### 2.2 Why the old reference lost — a second, real finding

Applying each chain to the **clean** signal (the best fidelity any denoiser
built from that chain could reach, 360 cells, correct SNR):

| Chain applied to the clean signal | Fidelity (dB) |
|---|---:|
| 0.5–40 Hz band-pass (starter) | 10.83 |
| median (0.6 s) + 50/60 Hz notches + **0.5–40 Hz band-pass** (old reference) | **9.04** |
| median (0.6 s) + 50/60 Hz notches + **40 Hz low-pass** (new reference) | **11.38** |
| 40 Hz low-pass alone | 28.07 |

The clean reference is the **raw** MIT-BIH record (recorded through a 0.1 Hz
hardware high-pass), so it still contains real low-frequency ECG content.
The 0.5 Hz high-pass corner was deleting that content — signal, not noise —
and paying a zero-phase transient cost over a 10 s (2-cycle) window. The
median stage already handles baseline wander, so the high-pass added only
loss. Under the old estimate-power metric that loss was invisible.

### 2.3 What changed

* `snr_db` is now error-based; `_score_performance` maps `+inf`
  (perfect reconstruction) to the documented `PERF_CEIL_DB = 30.0` and
  undefined cells to `PERF_FLOOR_DB = -10.0`, so every score stays finite.
* The reference chain keeps its documented stages (median baseline removal →
  mains notches → band limiting) but ends in a **40 Hz low-pass** and applies
  **both 50 Hz and 60 Hz** notches (skipping any at/above Nyquist). The
  0.5–40 Hz `bandpass_filter` remains available as a documented helper and as
  Project 2's band limiter.
* The offline synthetic generator was rewritten. It built each beat as
  `exp(-((t - k*rr) % rr)**2 / ...)`, i.e. a spike train at multiples of the
  RR interval; ten of them summed to ≈720 bpm with most energy above 40 Hz,
  so band-limiting denoisers looked *worse than their input* in offline mode.
  It now produces one P-QRS-T-like complex per beat at ≈75 bpm with
  respiratory sinus arrhythmia.
* A **new regression test** proves the metric cannot reward attenuation:
  scaling a high-SNR input by 0.5/0.1/0.01 must lose SNR, and the result must
  be far from the old `-20*log10(scale)` closed form.

## 11. Remaining limitations

- **Benchmark scope:** two MIT-BIH records (118, 119) and three NSTDB noise
  records. This is a small, fixed protocol meant to demonstrate an honest
  evaluation design, not a population-level claim; the absolute scores are
  protocol-specific and not comparable to published denoising papers.
- **Absolute scores are modest and negative at high input SNR.** At +18 and
  +24 dB the added noise is small relative to the clean record's own noise
  floor, so the honest error-based metric reports little or negative
  improvement. Reporting that is the point of the correction.
- **The clean reference is the raw MIT-BIH record.** It contains its own
  low-frequency content and residual baseline, which is why the reference
  does not apply a 0.5 Hz high-pass; benchmarks that instead define "clean"
  as a pre-filtered signal would favour a different pipeline.
- **Small headroom over the FFT alternative.** `fft_soft_threshold` reaches
  0.8229 vs the reference's 0.8366 under the corrected metric. It is
  documented as an alternative stage, not the submission.
- **Detector-driven classification is expected to be worse than
  annotation-centred.** Annotation positions are unavailable at inference;
  the two approaches confound peak positions, RR-feature definitions and
  label assignment, so the gap (RF 0.5014 vs 0.6413 balanced accuracy) cannot
  be attributed to any one factor. Recorded in
  `metrics.json.limitations`, not glossed over.
- **Rare-class performance in project-1 real data:** `S`/`F` recall is low;
  accuracy/weighted-F1 are dominated by the `N` class, so balanced accuracy
  and macro-F1 are the honest metrics (documented in the project README).
- **Project-3 real BIDMC precision** is limited by inter-channel alignment
  (monitor-reference bias). The HRV-vs-PRV findings (mean-HR agreement
  ~0.4 %, SDNN/RMSSD differences, LF/HF instability, independent series) are
  preserved as documented negative findings.
- **Offline fallback is synthetic.** CI has no PhysioNet data, so its strict
  margin tests run on the synthetic rhythm; the real-data numbers require the
  local data tree and are recorded in `expected_results.json`.
